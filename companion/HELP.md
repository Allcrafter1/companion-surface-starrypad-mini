# STARRYPAD MINI

This experimental surface module has been tested with a Donner STARRYPAD MINI,
**firmware 010**, on CompanionPi (Debian 13) with Companion 5.0.7.

## Usage

The device is detected through the `STARRYPAD MINI-Private` MIDI port. The
module selects Preset 1 / Bank 1 when it connects. A Companion page maps to the
16 pads in their physical layout:

| Row | Left to right |
| --- | --- |
| Top | Pad 13, 14, 15, 16 |
| Row 2 | Pad 9, 10, 11, 12 |
| Row 3 | Pad 5, 6, 7, 8 |
| Bottom | Pad 1, 2, 3, 4 |

Each pad triggers the corresponding Companion button. Its rendered background
color becomes the pad's RGB color. Steps and feedbacks, including Home Assistant
feedbacks, continue to work. The brief white flash on press is generated by the
device itself.

## Settings

**MIDI map** expects exactly 16 `channel:note` entries from top left to bottom
right. Use `-` to disable a control.

**RGB interval in ms** accepts values from 1 to 1000. The tested default is
1 ms. Zero is invalid because the hardware lost one write during a burst without
an interval.

## Safety and diagnostics

Only real color changes are written. Unchanged colors are deduplicated and rapid
updates are reduced to the latest value. Unknown internal control values are
left untouched; input remains active and RGB is disabled until the next
reconnect.

On Linux, a unique USB serial number gives each controller a stable Companion
identity even when ALSA client numbers change. The serial is hashed before it
is used. Devices without a unique serial use their physical USB port instead.
Two real controllers have not yet been available for a practical test.

Relevant log entries begin with `[SPM-`. When reporting a problem, include the
device model, firmware, operating system, Companion version, and matching log
lines:

https://github.com/Allcrafter1/companion-surface-starrypad-mini/issues

The M-VAVE SMC-PAD Pocket and SZ-STUDIOPAD-MINI may use related hardware, but
they have not been tested and are not currently detected automatically.
